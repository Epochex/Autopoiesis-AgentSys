# 两项演示与验收

在项目目录使用 root 执行，网关须已启动。两个脚本仅创建和操作专用
`autopoiesis-acceptance-*` 服务，每次使用唯一名称并拒绝覆盖已有服务。后台常态巡检忽略这些专用服务，演示脚本独占故障检测与处置。结束后清理服务，保留调查、记忆版本和变更回执。

## 答辩演示

```bash
cd /data/Autopoiesis-AgentSys
./scripts/demo_self_healing.py
./scripts/demo_memory_trajectory.py
./scripts/cleanup_demo_usecases.py
```

前两个命令各在约一分钟内完成。运行前停留在“网络态势”，新事件会在约 2 秒内弹出通知并保留约 10 秒；点击通知就在网络态势图上打开全链路剧场，处置链（巡检发现 → 二次确认 → 前置校验 → 执行动作 → 观察期 → 回读验证）随账本实时推进，右侧是逐条命令与回读结果。页面顶部的调查步骤条串起 01 案件事实 · 02 全链路剧场 · 03 调查依据 · 04 处置与回读 · 05 记忆观测舱，任一步可直接跳转。通知消失后，案件永久留在“事件中心”，点开受控演示行同样落在剧场。第三个命令在演示结束后统一删除两个受控用例产生的临时服务、回执、案件、会话、精确记忆和关联轨迹。

自愈用例：从通知进入全链路剧场，在处置链和执行面板上观察连续两次故障检测、变更前状态和 Diff、
仅匹配本次服务的一次性授权、重启和 4 次回读。Diff 预览保留约 4 秒，观察采样间隔 2 秒。
脚本负责执行，观看时无需手动审批；生产设备写入开关保持原值。
服务重启属于瞬时动作，无法撤销已经发生的重启，失败将留下人工处理回执。

记忆用例：从通知进入剧场后切到步骤 05 记忆观测舱，观察关闭记忆和开启记忆的两轮真实调查在语义 / 程序 / 情景三层记忆与上下文包里的读写。
第一轮生成唯一处理方法标识，脚本从持久化记忆接口回读，并验证来源包含第一轮会话。
第二轮必须召回和选中这个精确标识，随后比较两轮实际执行检查数。
步骤 01 案件事实展示六段因果链和记忆实际作用，内部选材快照、工作集版本、磁盘检查点与原始记录位于折叠的“技术审计记录”。
`modelContextSubmitted` 仅在确实发生模型调用且该记录进入模型输入时为真；本用例的已确认服务故障路径使用确定性检查决策。

验收对比两轮实际执行检查数，并单独记录候选检查数和请求耗时。
候选 4 项、执行 1 项与两轮实际检查量差异分别计量；耗时只作为诊断数据。
详情交互直接读取本案保存轨迹，不触发全量轨迹统计。

## 快速测试

```bash
./scripts/demo_self_healing.py --test
./scripts/demo_memory_trajectory.py --test
./scripts/cleanup_demo_usecases.py --dry-run
./scripts/cleanup_demo_usecases.py
```

使用同一条真实检测、执行和记忆路径。省去观看等待，自愈改为 1 秒间隔、4 次回读。
全部断言通过返回 0；失败返回非零并保存失败记录。失败历史保留，前端显示最新进展。
自愈失败条件包括前置状态不合格、动作范围超出单服务、执行回执缺失、恢复失败、保护检查失败和回读不足。
记忆失败条件包括第一轮记录未持久化、第二轮未召回精确记录、实际检查未减少、选材快照缺失、工作集版本不单调、磁盘检查点不一致或事件顺序不完整。

清理脚本从 `controlled_test` 回执提取精确的运行、服务、案件、会话、变更和记忆标识。`--dry-run` 只统计目标；正式执行期间会短暂停止网关，完成数据库和轨迹清理后自动启动网关并等待健康检查通过。
