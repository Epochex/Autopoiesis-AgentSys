# Autopoiesis 态势感知控制台 · UI/UX 完整设计 Prompt（中文版）

> 用途：把这份文档整段贴给任意模型作为系统/首轮 prompt，即可在**不看现有代码**的前提下，继续按同一套视觉与交互语言开发本项目的新页面、新组件。
> 优先级：本文档 > 模型自身审美默认值。凡与"通用现代 Web 设计最佳实践"冲突处，一律以本文档为准。

---

## 0. 你在做什么产品

一个**自演化长周期 Agent 系统（Autopoiesis）的运维控制台**：真实企业内网的网络根因分析（RCA）+ 安全态势 + 记忆演化 + 自我渗透验证。

- 使用者是网络运维工程师、安全分析师、以及评审这套系统的技术面试官。
- 界面呈现的是**一次真实系统运行的实录**，不是营销页、不是 mockup、不是 BI 报表。
- 产品有 **4 个页签 × 2 个场景**：
  - 页签：`态势 console` / `长轨迹 trajectory` / `自我渗透 pentest` / `混合检索 retrieval`
  - 场景：`内网实时 live` / `基准评测 bench`
  - **铁律：场景切换 = 只换数据源，不换 UI。** 同一页签在两个场景下渲染**同一套组件**，只是喂不同 endpoint 的数据。绝不为第二个场景另造一个"长得差不多"的新组件。

---

## 1. 设计信条（一句话）

**Light-paper technical instrument（浅色纸面技术仪器）+ editorial print（编辑排印）。**
冷静、精确、图解式、可审计、系统级、克制。看起来像一台仪器的读数面板 / 一份印刷的技术报告，而不是一个 SaaS 仪表盘。

判断标准：**"计算过程本身可见吗？读者能读到真实内容吗？"** 只要一个设计只能展示"结果的容器"而讲不清机制，就是错的。

---

## 2. 硬性禁止（这是本项目五轮返工换来的，逐条都别犯）

### 2.1 绝对不要的视觉
- ❌ **深色主题**。本控制台是 LIGHT。组件一旦发暗即视为坏掉。
- ❌ **卡片网格**作为页面主语言。"一格格带标题栏的模块"也算——卡片是静态容器，只摆结果，讲不清机制与算法。
- ❌ glassmorphism、neumorphism、毛玻璃、模糊、发光、阴影堆叠、大圆角玩具感。
- ❌ 装饰性 3D、渐变色块、彩虹图表配色、饼图、环图、仪表盘（speedometer）、雷达图（除非确实提升顶层对比）。
- ❌ 同屏出现**多个饱和强调色族**。一屏只允许一个强调色族。
- ❌ **AI 感 / 生成艺术**：单张自由画布 + 标尺 + 像素坐标读数 + 邻近连线 + 按数值缩放的圆。这类"看大小猜含义"的抽象编码被明确判为廉价。
- ❌ 纯抽象的算法示意图（缎带、分数条、D1/D2 文档别名）**作为整页主体**——看不出具体内容、看不懂到底干了什么。
- ❌ 反过来也不行：**干巴巴扔一堆文字**。

### 2.2 正解是什么
> **真实内容为主 + 流动可交互的 UX 承载。**

算法型页面（检索、渗透、轨迹）的正确形态是**可回放的真实案例实录**：
顶部真实案例切换 → ▶播放/暂停/点阶段跳步 → 每一步展开**真实的**文档标题+正文+命中词高亮+全程轨迹徽章 → 末步展示真正喂给下游的上下文段落与 token 预算填充。
抽象图形只能作为真实内容之间的**连接件**，不能是主体。

## 3. 设计令牌（照抄这些十六进制值，别自己调）

在每个组件 CSS 文件的根选择器里**重新声明一遍**这些 token，让组件自包含：

```css
.xx {
  /* 纸面 · 三层 */
  --paper:   #e7e7e3;   /* 页面底 */
  --paper-2: #efeee9;   /* 抬起面：hover、展开区、模块底 */
  --paper-3: #dddcd5;   /* 凹陷面：井、被遮蔽的空闲步骤、代码底衬 */

  /* 墨 · 文字与结构 */
  --ink:      #0d0d0d;  /* 主文字、2px 结构框（17.4:1） */
  --ink-soft: #2a2a27;  /* 次级正文 */

  /* 中性 */
  --gray: #605f5a;      /* 可承载文字的次级灰（4.94:1，达 AA） */
  --rule: #cfcfca;      /* 只做发丝分隔线，绝不承载文字 */
  --quiet:#8c8c88;      /* 只做图形描边的静默标记，绝不承载文字 */

  /* 唯一强调色 */
  --acid:     #ccff00;
  --acid-ink: #0d0d0d;

  /* 严重度族（仅算法/安全页使用） */
  --hi:  #c3384a;       /* 高危 / 外部攻击（别名 --hot、--wan） */
  --mid: #a86a12;       /* 中危 / 观察（别名 --amber） */
  --lo:  #8a8a86;       /* 低危 / 信息 */

  /* 内网/结构族 */
  --teal:    #12615c;   /* 作为文字用（5.4:1），内网、只读安全、防线成立 */
  --net:     #1c8f88;   /* 作为图形描边用 */
  --wan-ink: #a5233a;   /* 危险作为文字用（5.0:1） */

  /* 层级（结构身份，不是威胁等级） */
  --tier-core:   #0d0d0d;
  --tier-subnet: #2a2a27;
  --tier-edge:   #605f5a;
  --tier-leaf:   #8c8c88;

  /* 字体 */
  --font-display: 'IBM Plex Sans Condensed', sans-serif;  /* 600 字重，仅标题 */
  --font-mono:    'IBM Plex Mono', monospace;             /* 400/500，正文与一切数据 */

  /* 动效 */
  --ease-guide: cubic-bezier(0.2, 0, 0, 1);
  --t-mark:  160ms;   /* 标记态变化 */
  --t-point: 240ms;   /* 指向 */
  --t-set:   300ms;   /* 落位 */
  --t-wipe:  360ms;   /* 擦除揭示 */
  --t-count: 500ms;   /* 数字滚动 */
}
```

### 3.1 强调色法则（最容易被违反，务必守住）
- `--acid #ccff00` 是**唯一**强调色，且**只能做填充**（背景），**永远不许作为纸面上的纯文字**（对比度不足）。
- 它只有一个语义，且每屏只能有一个语义：**交互态**——被选中 / 被 Agent 作用的对象 / 当前这一步发生了变化。
- 它**绝不能**编码层级、严重度、分类。区分类别要靠**结构**：框线粗细、斜纹填充、点阵、分隔线位置、虚实线，而不是加一个新颜色族。
- 在态势页（console），严重度**完全靠墨色轻重 + 结构**表达，不靠色相：高危=满墨实心标记+斜纹/涟漪环，观察=灰色实心+虚线环，正常=纸面空心标记。
- 危险红 / 内网青这两个色族只允许出现在**互斥的两个屏**上（WAN 入侵视图 vs 下钻网段视图），永不同屏。

## 4. 排印规范

| 角色 | 规格 |
|---|---|
| 页面大标题 | `--font-display` 600 / `clamp(30px, 3.2vw, 52px)` / `line-height:.9` / `letter-spacing:-.02em` / 全大写；其中关键词用 `<mark>` 包裹 → `background:var(--acid); color:var(--acid-ink); padding:0 .05em` |
| 标题上方的编号/kicker | 9.5px / `letter-spacing:.2em` / 全大写 / `--ink-soft` |
| 论点句（标题下一行） | 12.5px / `line-height:1.5` / `--ink-soft` / `max-width:88ch` |
| 章节标签 | 10.5px / 600 / `.1em` / 全大写 / `border-bottom:2px solid var(--ink)` |
| 正文 | 11–13.5px mono / `line-height:1.45–1.5` / 阅读宽度上限 78–88ch |
| 微标签、pill、单位 | 8–9.5px / `letter-spacing:.06–.12em` / 全大写 |
| 大数字 | 26px / `font-variant-numeric: tabular-nums` / 单位用 `.38em` 的内联 `<i>` 且着色 `--gray` |

- 全站正文字体是 **等宽 mono**，不是无衬线。无衬线（Condensed）只用于大标题。
- 一切数字必须 `font-variant-numeric: tabular-nums`，避免跳动。
- 不要超大装饰性标题喧宾夺主；不要低对比度弱正文。

## 5. 框线与几何

- `border-radius: 0` —— **整个项目几乎为零**。每个 CSS 文件最多允许一处例外（例如画一个锁形图标）。
- **2px solid var(--ink)** = 结构级分隔：页头下边线、章节标签下划线、场景切换器外框、指标条的左侧竖线。
- **1.5px solid var(--ink)** = 模块外框、选择器外框、命令块外框。
- **1px solid var(--rule)** = 发丝分隔线、pill 边框、列表行分隔。
- **border-left: 2–3px** = 状态/严重度编码（行左侧竖条），配合 `--hi/--mid/--lo` 或 `--teal`。
- **禁止**：box-shadow 做层次、圆角做柔化、渐变做填充。层次靠**纸面三层 + 框线粗细**表达。
- 画布底纹（拓扑图/流程图背景）：`linear-gradient(rgba(13,13,13,0.05) 1px, transparent 1px)` 双向，格子 46–48px；密网格叠加时用 1/4 格 + `0.03` 透明度。
- 危险/需审批区域用 **45° 斜纹**：`repeating-linear-gradient(-45deg, transparent 0 7px, color-mix(in srgb, var(--hi) 6%, transparent) 7px 8px)`。

## 6. 组件语汇（这些是本项目的"词"，新页面直接复用）

1. **页头 masthead**：kicker 编号 → 大标题（含 acid `<mark>`）→ 论点句 → 目标行（授权范围/CIDR/时间）；右侧是**指标条**（每个指标 `border-left:2px solid var(--ink)`，大数字 + 8px 全大写标签）。
2. **章节**：一条 2px 墨线 + 其上的全大写标签，不要卡片外壳。
3. **选择器/切换器**：一排按钮包在 1.5–2px 墨框里，按钮之间用同粗墨线分隔；选中态 = 墨底 + acid 字（主切换）或 `--paper-3` 底（次级切换）。
4. **结论列表（findings）**：每行左侧 3px 严重度竖条 → 严重度数字（tabular）→ 类型 pill（墨底或 `--hi` 底反白）→ 标题 → 主机/端口 → 右侧状态 pill（🔒需审批 = 墨框，👁只读 = teal 框）。整行是一个按钮，**就地展开**，不要弹窗。
5. **展开区 = 可运行 playbook**：目标 → 授权前提（`--paper-3` 底 + 2px 墨左条）→ 编号步骤（左 2px teal 竖条；入侵型步骤换成 `--hi` + 45° 斜纹）→ 每步的 只读/入侵 模式 pill → **命令块**（墨底、`#e9e9e2` 等宽字、右侧 34px 复制按钮、按钮字符用 acid）→ 判定二栏（确认/缓解）→ 整改建议 → 证据 id 链。
6. **回放走带 transport**：`▶/❚❚` + 进度条 + 计数「事件 i/N · 轮 Pn」；网格/步骤随 playhead 逐格揭示，当前格用 acid 细框标 `now`，数字用 count-up 动画。
7. **拓扑画布**：整幅出血 SVG，按 厂商/层级 聚类（向日葵螺旋排布），曲线边，hover 点亮邻域子树并在右上角出详情面板，支持缩放平移，顶部面包屑返回全局。**基准场景复用同一个组件**，只是把记忆图谱映射成同样的数据形状喂进去。
8. **实录块（算法页主体）**：真实文档标题 + 真实正文 + **命中词高亮** + 命中 chips + 全程轨迹徽章（命中# → 融合# → 门控保留 → 上下文 t），点击展开真实全文。
9. **诚实降级标记**：不可用的能力**要标注，不要调暗**。做法 = 名称加删除线 + 一个 1px 框的「Off」小 chip（`--gray` 字）。绝不用 `opacity:.4` 把它压到读不清——那是隐藏事实而不是陈述事实。
10. **搜索栏**：防抖输入 + 结果下拉，每条结果左边框用严重度色，选中后触发下钻并聚焦目标。

## 7. 交互与动效

**动效必须是结构性的，不是娱乐性的。**

- 允许：线条生长、遮罩擦除揭示（wipe）、定向滑入、注释连线描绘、裁切面板转场、数字 count-up、图表克制入场。
- 禁止：弹性/回弹（spring/bounce）、hover 放大、炫技英雄转场、普通操作的庆祝动画、任何 glow。
- hover/focus 的强调方式：线条激活、标记点亮、细微对比变化、边框/下划线/边缘描绘。**不许**靠大阴影或缩放。
- 标准揭示关键帧：`from { opacity:0; transform:translateY(-4px) } to { opacity:1; transform:none }`，`.35s ease`。
- **每个动画都必须有** `@media (prefers-reduced-motion: reduce)` 退路：直接全量显示，不是放慢。
- 键盘可达：控件、表格、抽屉都要能键盘操作。

## 8. 诚实性铁律（本项目的灵魂，迁移时必须带走）

界面渲染的是一次**真实的内核运行**。因此：

1. **每一个视觉标记 = 一条真实数据。** 前端绝不合成位置、分数、原因、diff 再当作系统行为展示——这正是这套 UI 重建要消灭的问题。
2. **值不存在就在界面上说出来**，不要填补空白。后端会通过 `capabilities` 报告哪些能力真的接上了，尊重它。
3. **不要把常量渲染成看起来会变的量**（例如衰减未接线时 strength 恒为 1.0，就不能画成变化曲线）。
4. **如实报计数**：触发次数取自真实 trace，不要编造；台架/评测专用的数据要标注为"仅台架"。
5. **不许编造自问自答的 query**，一律取真实用例文本。
6. **门控要可见**：只读步骤标"安全"、可直接复制运行；入侵/利用步骤标红 + 斜纹 + "需审批·勿直接跑"，且**不给可武器化载荷**（写 `# GATED · payload/wordlist withheld`）。
7. **关键状态不能只靠颜色**，必须同时有文字或结构。
8. 未跑通的部分老实标"待运行/公开基线参照"，不伪造本地分数。

## 9. 页面架构模板

复杂分析页按这个顺序组织，**不要把所有内容摊成一面滚动墙**：

1. **头部/控制层** —— 标题、场景与数据集选择、模式切换、导出。
2. **摘要层** —— 紧凑指标条、关键差值、当前对比上下文。
3. **分析主体** —— 分区/分步；每区一个主视图（实录、拓扑、流程）+ 必要的次级拆解。
4. **证据/样例层** —— 可搜索可排序的表、行级下钻、结构化详情面板。
5. **审计层** —— 证据映射、回放元数据、状态与失败标记、可导出细节。

图表选择：优先分组柱、堆叠柱、热力图、箱线图、散点、分布、结构化表格、A/B 对比面板、证据引用映射。每个图必须回答一个明确的分析问题；回答不了就删。

## 10. 技术栈与代码约定

- React 19 函数组件 + TypeScript + Vite。字体用 `@fontsource/ibm-plex-mono` 与 `@fontsource/ibm-plex-sans-condensed`。
- **纯手写 CSS 文件，一个组件一个 `.css`**。没有 Tailwind，没有 UI 组件库，没有 CSS-in-JS。
- 每个组件用**唯一短前缀命名空间**（`pt-` 渗透 / `rt-` 检索 / `tb-` 基准轨迹 / `fx-` 轨迹 HUD / `ls-` 实时态势 / `mg-` 记忆图 / `bt2-` 基准拓扑），避免全局碰撞。
- 组件根选择器里重声明 token + `.xx *, .xx *::before, .xx *::after { box-sizing: border-box; }`。
- 可视化**手写 SVG** 为主（拓扑、桑基缎带、星座图、流程）；echarts 仅在标准统计图时使用；three/@react-three-fiber 仅用于唯一那个 3D 场景。
- 数据来自 `/api/rca/*`，TS 接口显式定义；场景通过 `?scenario=live|bench` 查询参数切换，并且**必须进 `useEffect` 依赖数组**。
- 中英双语：所有面向用户的文案走 `i18n.ts` 的 `lang: 'zh' | 'en'`。
- 组件小而可复用、props 显式；页面编排与展示组件分离；不要出现混杂渲染+取数+样式的巨型页面文件。
- 替换页面时**显式删除废弃文件**，不要留下两套并存的页面系统。

## 11. 验收清单（Definition of Done）

一个 UI 任务只有全部满足才算完成：

1. 视觉与本文档的浅色纸面编辑体系一致；没有任何组件跑成深色。
2. 一屏只有一个强调色族；`--acid` 只表示交互态，且从未作为纸面纯文字出现。
3. `border-radius` 为 0（除至多一处画图标的例外）；层次靠纸面三层与框线粗细，没有阴影/毛玻璃。
4. 页面主体是**真实内容 + 可交互流动**，不是卡片网格、不是抽象示意图、不是纯文字。
5. 每个视觉标记都能追到真实后端数据；不可用能力被显式标注而非隐藏或伪造。
6. 所有动效结构化，且有 `prefers-reduced-motion` 退路；对比度达 AA；关键状态不只靠颜色。
7. 被替换页面的死代码已删除；组件模块化可读。
8. `npm run lint` / `tsc -b` / `npm run build` / 相关测试通过；跑不了的要说清为什么，不许无验证就宣称成功。

## 12. 交付回答格式（大改造时）

按顺序回答：① 当前理解 → ② 改造方案 → ③ 增/删/改文件清单 → ④ 实现摘要 → ⑤ 已做的验证 → ⑥ 遗留占位与风险。状态更新保持紧凑具体。
